Engineered for massive multi-megawatt pre-training pods. Focuses on maximum dense matrix throughput, native FP4 precision, and high-density SerDes routing.

  • Memory Subsystem: 288 GB HBM4 @ 8.60 TB/s

2. Silicon Microarchitecture & Memory Hierarchy

Analysis of compute engines: TPU 8t’s 256x256 FP4 MXU & VPU scaling vs. TPU 8i’s Collectives Acceleration Engine (CAE) and 384 MB VMEM KV-cache staging buffer.

TPU 8t: Dense Matrix Engine & VPU Overlap

The primary compute core incorporates a 256x256 systolic array Matrix Multiply Unit (MXU) operating on native FP4 math. Transitioning to FP4 doubles tensor operational density per clock cycle to 12.6 PFLOPs per chip while cutting MAC energy consumption.

VPU Pipeline Overlap Mechanics:

LayerNorm, Softmax, and dynamic quantization routines previously caused sequential execution stalls. TPU 8t scales the Vector Processing Unit (VPU) to run auxiliary operations concurrently with active systolic matrix multiplies, eliminating tail delays.

SparseCore Acceleration: Retains specialized hardware blocks to offload sparse embedding lookups and asynchronous all-gather operations in dynamic recommendation systems and multimodal tokenizers.

TPU 8i: CAE & Extended 384 MB SRAM Hierarchy

TPU 8i replaces SparseCores with two Tensor Core dies and a dedicated Collectives Acceleration Engine (CAE) on the chiplet boundary, operating alongside a 3x enlarged 384 MB VMEM SRAM buffer.

Collectives Acceleration Engine (CAE):

Functions as an autonomous reduction engine managing ring/tree reductions and cross-node sampling without host CPU intervention. Cuts on-chip collective latency by up to 5x during token decoding.

384 MB Zero-Latency KV Staging: Acts as an on-chip staging buffer for active attention working sets. Attention kernels stream Key-Value tiles directly to execution units without HBM round-trip penalties.

3. Interconnect Fabrics & Multi-Scale Topologies

Explore the hierarchical Boardfly topology (Km complete graphs) for inference vs. TPU 8t 3D Torus and the data center-scale Virgo fabric.

Hierarchical Dragonfly

The Boardfly Scale-Up Topology

While 3D Tori scale well for dense grid stencils, their network diameter scales as Θ(N1/n), incurring severe multi-hop latency during dynamic Mixture-of-Experts (MoE) dynamic token routing.

3-Tier Hierarchy (Km Complete Graphs):
  • Building Block (BB): 4 chips in direct ring.
  • Group (G): 8 BBs (32 chips) via copper backplane.
  • Pod Fabric: 36 Groups (1,152 chips) via Apollo MEMS Optical Switches (K36).

Strict Diameter Bound: For any arbitrary chip traversal requiring optical inter-group transition (g = 1), maximum diameter is strictly bounded to 7 hops max (56% drop vs. 1024-chip 3D Torus).

4. Software Stack, TorchTPU & Programmability

Transitioning from legacy `torch_xla` lazy tracing to native eager-first TorchTPU execution, PJRT plugins, and Pallas DSL kernel authoring.

TorchTPU vs. Legacy torch_xla

Eager First

Historically, `torch_xla` required lazy tensor graph tracing. Dynamic shape changes caused recompilation storms and trace capture stalls. TorchTPU (co-developed with Meta) integrates first-class native PyTorch execution.

Legacy torch_xla (Lazy Tracing Path):
Python Exec → Lazy Graph Trace → Dynamic Shape Recompile → XLA AOT

High tracing overhead; dynamic control flow triggers compilation stalls.

TorchTPU (Eager Execution Path):
torch.device("tpu") → Eager Exec → Pre-Compiled Kernels → FSDP2/TP Link

Line-by-line debugging (`pdb`), native dynamic loops, pre-compiled transformer layer library.

Pallas DSL & Ecosystem Integration

For low-level hardware control, Google provides Pallas, a Python-embedded domain-specific language (DSL) for manual VMEM staging and custom kernel design.

Pallas Kernel Capabilities

Explicit systolic tiling geometry, custom attention algorithms, dynamic KV cache staging, and CAE/SparseCore programming.

MaxText & Tunix

MaxText JAX framework for max MFU training; Tunix for SFT and Reinforcement Learning with Verifiable Rewards (RLVR).

Inference Runtimes

Native support for vLLM, SGLang, and JetStream with PagedAttention optimized for 384 MB VMEM.

Orchestration Layer

GKE Inference Gateway with predictive sequence length capacity routing cuts TTFT by up to 70%.

Execution Determinism vs dynamic SIMT

NVIDIA’s dynamic SIMT warp scheduling introduces runtime jitter during multi-node collective synchronization. TPU 8t enforces ahead-of-time (AOT) static compilation, eliminating cache-miss jitter and sustaining high Model FLOP Utilization (MFU) across 9,600-chip domains.

TCO Insulation via Co-Design Partnerships

By deploying the cost-optimized MediaTek TPU 8i for serving and allocating the Broadcom TPU 8t exclusively for pre-training, Google insulates its cloud operational cost structure from merchant GPU supply constraints and pricing volatility.
