## Notable Microarchitecture Features

- **Tensor Memory Accelerator (TMA):** a dedicated DMA engine — one thread submits a multi-dimensional tile descriptor (base address, leading dimension, swizzle), the engine does all address arithmetic and writes into shared memory, and completion is signalled by an `mbarrier`. The whole warp is freed from load issue and address math. Also supports **cluster-level multicast**: one HBM read fans out to every SM in a thread-block cluster, turning N separate loads into one
- **`wgmma.mma_async`:** Hopper widened the matmul issuer from a 32-thread warp to a **128-thread warp group** at 64×256×16 shape, moved B into a shared-memory descriptor (A optional: registers or descriptor), and made it **return immediately** — the matmul runs in the background while the warp group queues the next tile, tracked via `wgmma.commit_group` / `wgmma.wait_group`
- **Warp specialisation:** the Hopper-era idiom — inside one block, *producer* warps issue back-to-back TMA loads while *consumer* warps fire `wgmma` on freshly-arrived tiles, handshaking through `mbarrier` and async transaction barriers rather than block-wide `__syncthreads()`. This is the recipe behind FlashAttention-3, CUTLASS ping-pong GEMMs, and the Blackwell FA4 kernel — and it works only because the matrix instruction does not block the warp
- **4th-gen Tensor Cores:** native FP8 (E4M3 / E5M2) with hardware scaling
- **Transformer Engine:** auto-casts between FP16 and FP8 per layer to maximize throughput
- **NVLink 4:** 18 links × 25 GB/s each = 900 GB/s bidirectional per GPU; enables NVLink Switch fabric
- **HBM3 stack:** 5 stacks × 16 GB, 3.35 TB/s aggregate

## SM Structure (per SM)

- 4 warp schedulers
- 4 dispatch units
- 128 FP32 CUDA cores (32 per partition)
- 4× 4th-gen tensor cores (one per partition)
- 256 KB register file
- 228 KB configurable L1/shared memory

## Why the async matmul matters

A transformer block is ~99% matmul FLOPs, so the Tensor Cores carry the throughput while
CUDA Cores own everything else (activations, residual adds, normalisation, address
arithmetic). The reason Hopper's *asynchronous* matmul is the generational story rather
than a footnote: because `wgmma` does not block the issuing warp, that warp can run
softmax, apply a mask, or preload the next tile **while the matmul is in flight**. The
overlap of matmul with the surrounding element-wise work is the structure of every
modern attention kernel. See
[attention](../../workloads/attention.md) and
[AI chip architectures](../architectures.md#nvidia-gpu--programmability) for how this
compares to AMD's wavefront-scoped MFMA, which offers the issuing wave no equivalent.
